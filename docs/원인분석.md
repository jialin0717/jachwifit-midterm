# 자취핏 원인 분석

## 1 분석할 문제

**좁은 자취방의 수납용품을 고르는 대학생은 여러 후보의 가격·치수·용도를 자신의 공간·예산과 대조할 때 판단 부담을 느낄 수 있다.** [사용자 저니](저니.md)의 3단계인 ‘가격과 치수 비교’를 LOW POINT로 놓고, 이 부담이 생기는 원인과 자취핏 v2의 대응을 분석한다.

분석의 우선순위는 **기능 추가보다 비교 정보의 우선순위와 표시 순서를 정하는 것**이다. IKEA에 가격·치수·필터가 없어서 생기는 문제로 보지 않는다. 비교 부담과 최저점은 가상 퍼소나에 기반한 설계 가설이며 실제 사용자 관찰 결과가 아니다.

## 2 근거와 가정 구분

| 구분 | 확인하거나 참고한 내용 | 분석에 사용하는 범위 |
|---|---|---|
| 리뷰 근거 | R01은 조건에 맞는 상품 탐색의 불편, R02는 구체적 분류의 장점, R03은 3D를 통한 공간 판단의 장점을 다룸 | 조건 탐색과 공간 확인이 중요하다는 시사점. 과거 개인 리뷰를 현재 앱의 결함으로 일반화하지 않음 |
| 참고 UI 확인 | IKEA 화면에 가격·치수·필터가 이미 제공됨 | 정보의 부재가 아니라 자취방 수납이라는 특정 과제에 맞춘 정보 구성에 집중 |
| 설계 가설 | 후보를 오가며 가격·가로·깊이·높이를 기억하고 대조하는 일이 부담일 수 있음 | 피쉬본과 5 Why의 중심 가설. 부담의 크기와 실제 발생 여부는 추가 검증 필요 |
| 자취핏 구현 확인 | 목록·상세·추천 예시와 로컬 조회 오류 후 서버 재시작·재시도 복구를 확인함 | 자취핏의 구현과 복구 경로를 설명하는 근거. IKEA의 API·네트워크 장애 근거가 아님 |

## 3 피쉬본 분석

### 여섯 가지 원인 범주와 문제의 연결

아래는 피쉬본의 텍스트 도식이다. **가설은 비교 부담의 원인 후보**, **위험은 실제 발생을 확인하지 않은 기술적 가능성**을 뜻한다. 서로 다른 근거 수준의 항목을 확정된 원인처럼 합치지 않는다.

```text
       모바일 UX                  사용성                    데이터
       좁은 화면에서               후보 간 조건을             치수 방향·단위 또는
       정보 확인 위치 이동          기억하며 대조              정확성이 불명확할 위험
       [가설]                      [가설]                    [위험]
             \                       \                         \
--------------\-----------------------\-------------------------\----> 가격·치수·용도
              /                       /                         /       비교의 판단 부담
             /                       /                         /        [문제 가설]
       API                       네트워크                  프로세스
       조회 실패 시                지연·연결 단절 시            공간 측정·예산 설정·
       비교 정보 확인 중단          확인 흐름 중단               후보 판단을 직접 수행
       [위험]                     [위험]                     [가설]
```

### 가지별 원인 후보와 대응

| 가지 | 원인 후보 또는 위험 | 근거 수준 | 자취핏 v2의 대응과 한계 |
|---|---|---|---|
| **모바일 UX** | 작은 화면에서 여러 후보를 살피면 스크롤과 화면 이동으로 정보 확인 위치가 달라질 수 있음 | R01의 과거 모바일 탐색 경험을 참고한 가설 | A에서 가격·치수·용도를 같은 순서로 표시. 좁은 화면은 목록, 600dp 이상은 격자. 이동 횟수 감소는 미측정 |
| **사용성** | 이전 후보의 가격·치수를 기억하면서 현재 후보와 대조하면 인지 부담이 커질 수 있음 | 저니 3단계의 핵심 설계 가설. R02는 조건을 드러내는 구성의 간접 시사점 | A·B에서 비교 정보를 읽을 수 있게 구성하고 B에 표시용 조건 태그 제공. 후보를 나란히 놓는 비교 기능은 없음 |
| **데이터** | 치수 방향·단위가 불명확하거나 값이 부정확하면 공간 적합성을 잘못 판단할 수 있음 | 잠재 위험. IKEA 데이터 오류를 확인한 것은 아님 | 가격·가로·깊이·높이·용도를 명시. 현재 값은 모의 데이터이며 실측·정확성 검증 자료가 아님 |
| **API** | 상품·사용 안내 조회가 실패하거나 빈 결과를 반환하면 확인 과정이 끊길 수 있음 | 잠재 위험. 자취핏 로컬 조회 실패·복구는 확인했으나 IKEA API 결함 근거는 없음 | JSON GET의 로딩·오류·빈 상태를 구분하고 다시 시도 제공. 서버가 중지된 경우 서버 복구가 먼저 필요 |
| **네트워크** | 느린 연결이나 연결 단절로 정보 확인이 지연될 수 있음 | 잠재 위험. 별도의 저속·단절 실험이나 IKEA 네트워크 분석은 하지 않음 | 로딩과 조회 실패 상태로 현재 상황을 안내. 오프라인 이용이나 연결 자동 복구는 구현하지 않음 |
| **프로세스** | 사용자가 공간 측정, 예산 설정, 후보 대조를 각각 수행하므로 확인할 조건을 놓칠 수 있음 | 가상 사용 시나리오의 가설. R03은 공간 확인 가치의 간접 근거 | B에서 상품 정보와 사용 안내를 구분하고 C에서 후보와 이유를 예시로 표시. 공간 입력·자동 적합성 판정·조건 저장은 없음 |

## 4 우선 원인 선정

**우선 검토할 원인: 가격·치수·용도를 후보마다 다시 찾아 기억하고 대조해야 하는 정보 확인 부담.**

- **목표와의 관련성:** 저니 3단계와 ‘공간·예산에 맞는 후보 선택’이라는 사용자 목표에 직접 연결된다.
- **근거와의 연결:** R01의 조건 탐색 불편, R02의 구체적 분류 장점, R03의 공간 판단 가치를 함께 반영한다. 어느 리뷰도 현재 비교 부담의 크기를 입증하지는 않는다.
- **구현 가능성:** 현재 과제 범위에서 A·B의 표시 순서와 정보 구성을 조정할 수 있다. 확인되지 않은 IKEA API·네트워크 문제를 주원인으로 삼는 것보다 설계 범위에 적합하다.

따라서 먼저 정보 구성 가설을 5 Why로 구체화한다. 기술적 위험은 별도로 상태 안내와 복구 경로를 점검한다.

## 5 우선 원인에 대한 5 Why

**출발 문제:** 좁은 자취방의 수납용품 후보를 비교할 때 판단 부담이 생길 수 있다.

| 단계 | 왜 그런가 | 원인 가설 |
|---|---|---|
| **Why 1** | 왜 후보 비교가 부담스러울 수 있는가? | 가격뿐 아니라 가로·깊이·높이·용도까지 여러 조건을 함께 판단해야 하기 때문이다. |
| **Why 2** | 왜 여러 조건을 함께 판단하기 어려울 수 있는가? | 후보를 바꿔 볼 때 이전 후보의 값을 기억하거나 다시 확인하며 자신의 공간·예산과 대조해야 하기 때문이다. |
| **Why 3** | 왜 기억하거나 다시 확인하는 부담이 생길 수 있는가? | 후보별 정보를 읽는 동안 주의가 여러 항목과 화면에 분산되어, 같은 비교 기준을 이어서 확인하기 어려울 수 있기 때문이다. |
| **Why 4** | 왜 비교 기준에 주의를 유지하기 어려울 수 있는가? | 폭넓은 쇼핑 목적을 담는 정보 구성과 ‘작은 공간·정해진 예산에 맞는 수납용품 선택’이라는 좁은 과제의 우선순위가 다를 수 있기 때문이다. |
| **Why 5** | 왜 특정 과제와 정보 구성의 우선순위가 어긋날 수 있는가? | 이 사용 과제에 필요한 가격·치수·용도를 우선 정보로 정하고 같은 순서로 배치하는 기준이 없으면, 범용 정보를 나열하는 데 그칠 수 있기 때문이다. |

**도출한 근본 원인 가설:** 자취방 수납이라는 특정 과제에 맞춘 **비교 정보의 우선순위와 일관된 제시 기준이 부족할 경우**, 사용자의 기억·재확인 부담이 커질 수 있다.

이는 자취핏이 해결 대상으로 삼은 설계 수준의 원인 가설이다. IKEA 내부 구조나 개발 과정의 실제 원인을 규명한 결과가 아니며, 5 Why의 연결도 사용자 평가로 확인해야 한다.

## 6 원인 가설을 반영한 설계

| 설계 대응 | 원인과의 연결 | 현재 구현 범위 |
|---|---|---|
| **A 목록의 정보 순서 통일** | 비교 기준을 쉽게 찾도록 가격·치수·용도를 일정한 순서로 제시 | 모의 상품 4개. 사용자가 직접 읽고 비교하며 검색·필터·자동 비교는 없음 |
| **B 상세의 조건 태그와 정보·사용 안내 구분** | 조건을 기억에만 의존하지 않고 다시 확인하고, 사용 전에 필요한 설명으로 이동하도록 구성 | 태그는 표시용이며 선택 필터가 아님. 안내는 모의 데이터이며 빈 상태·조회 오류·재시도 제공 |
| **C 고정 후보와 이유 표시** | 후보를 검토할 때 어떤 조건을 볼 수 있는지 예시로 제시 | 어느 상품에서 열어도 같은 후보 3개. 실제 AI 분석·개인화·공간 적합성 판정은 하지 않음 |

## 7 검증 계획과 결론

향후에는 같은 공간·예산 조건으로 수납용품 후보를 고르는 과제를 제시하고 다음을 확인한다. **아래는 아직 수행하지 않은 계획이다.**

1. 가격·가로·깊이·높이를 정확히 찾아 대조하는지, 어떤 값을 다시 확인하는지 관찰한다.
2. 비교에 걸린 시간, 화면을 다시 방문한 횟수, 조건 누락과 사용자가 설명하는 부담을 기록한다. 정보 순서 통일의 효과는 이 결과를 보고 판단한다.
3. 저니 3단계가 실제 최저점인지 확인하고, 아니라면 우선 원인과 저니를 수정한다.
4. 표시용 태그와 고정 추천 예시를 필터·개인화·적합성 보장으로 오해하지 않는지 확인한다.

**결론:** 자취핏은 ‘정보가 없다’가 아니라 ‘특정 과제에서 여러 조건을 대조하는 부담이 있을 수 있다’는 문제에서 출발한다. 여섯 가지 원인 후보 중 정보 확인 부담을 우선으로 삼고, 가격·치수·용도를 같은 순서로 제시했다. 구현 여부는 확인했지만 비교 시간 단축이나 선택 오류 감소는 아직 검증하지 않았다.
