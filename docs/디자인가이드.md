# 디자인 가이드 — 자취핏

> 자취핏의 중간고사 UI 구현, IKEA 리뷰 참고 근거, 촬영한 데모를 정리한다.
> 핵심은 목록에서 가격과 치수를 읽고 상세에서 용도를 확인하는 흐름이다.
> 코드의 화면별 대응표와 이 문서의 요소 번호·위젯명·비즈니스 명칭을 일치시킨다.

## 1. 화면 목록과 흐름

- 앱 이름: 자취핏
- 대상 사용자: 좁은 자취방에서 수납용품을 고르는 대학생.
- 설계 가설: 상품의 가격·치수·용도를 같은 순서로 보여 주면 공간과 예산을 살펴보기 쉽다.
- 유사앱: IKEA. Google Play 리뷰 4건(R01–R04)을 참고했으며, 수집 정보와 해석 범위는 `리뷰분석.md`에 정리했다.
- `db.json`은 가상 상품과 모의 사용 안내다. IKEA 실제 상품이나 실제 사용자 리뷰가 아니다.
- 가격·치수는 목록과 상세의 핵심 비교 정보다. 태그는 조건을 보여 주는 표시이며 실제 검색·필터·추천 계산은 구현하지 않는다.
- 상품 이미지는 AI로 생성한 가상 수납용품 이미지 4장이다. IKEA 상품 사진을 사용하지 않는다.
- 실제 AI API·로그인·결제·영구 저장·상태관리 패키지는 사용하지 않는다.

| 화면 | 이름(비즈니스 명칭) | 파일 | 들어오는 방식 | GET |
|---|---|---|---|---|
| A | 수납용품 목록 | `lib/screens/a_list_screen.dart` | 첫 화면 | `/items` |
| B | 수납용품 상세 | `lib/screens/b_detail_screen.dart` | 쌓기(push) — A 상품 선택 | `/notes?itemId=숫자` |
| C | AI 추천 예시 | `lib/screens/c_result_sheet.dart` | 덮기(modal) — B 버튼 | 없음 — 미리 작성한 상수 |

```text
A 수납용품 목록
 └─ 쌓기(push) → B 수납용품 상세
                  ├─ 옆으로(tab): 상품 정보 | 사용 안내
                  └─ 덮기(modal) → C AI 추천 예시
B → A: 뒤로 가기(pop)
C → B: 닫기(pop)
```

- 상품·사용 안내의 JSON GET 요청은 `lib/api.dart`에 둔다. 이미지 파일은 `Image.network`를 통해 같은 로컬 서버에서 읽는다.
- A는 `LayoutBuilder`로 가용 너비를 확인한다.
- 600dp 미만은 목록, 600dp 이상은 격자로 표시한다.
- C는 어떤 상품에서 열어도 같은 세 추천 예시를 표시한다.

## 4. 디자인 가이드 글

### 수납용품 카드 목록과 격자

목록에서 가격과 치수를 먼저 살펴보고 상세로 이동하도록 구성했다. 카드에는 상품명, 원 단위 가격, 가로·깊이·높이(cm), 용도를 같은 순서로 표시한다. 가용 너비가 600dp 미만이면 목록, 이상이면 격자로 전환한다(P02·P04·P08).

R01의 탐색 불편과 R02의 구체적 정보에 대한 긍정 평가를 함께 참고했다. 정보를 무조건 줄이기보다 비교에 필요한 가격과 치수를 남겼다. B-4의 태그는 조건을 읽는 용도이며 누르는 필터가 아니다.

### 상품 오류 안내와 다시 시도

조회에 실패하면 실패 안내와 다시 시도 버튼을 보여 준다(P09). R04의 결제 사례에서 얻은 시사점은 작업 결과를 명확히 알리는 것이며, 이번 앱에는 이를 조회 상태 안내로 적용했다. 재시도 버튼은 Future를 다시 요청한다.

### 사용 안내 목록

설치할 공간뿐 아니라 카트의 이동 통로, 의자와 다리를 움직일 공간도 확인하도록 모의 안내를 작성했다(P05). 안내와 작성일을 표시하며, 안내가 없는 상품 4에서는 빈 상태와 상품 정보 탭을 확인하라는 문구를 보여 준다(P01). 실제 구매 후기나 자동 공간 검증 기능은 아니다.

### AI 추천 예시와 관심 상품 체험

상세에서 모달을 열어 세 후보의 가격·치수와 추천 이유를 확인하고 닫기로 돌아온다(P03·P06·P07). 선택 상품명은 바뀌지만 추천 목록은 항상 같다. C-2·C-4에 고정 예시이며 실제 AI 분석이나 추천 계산을 하지 않는다고 안내한다(P01·P10).

관심 상품 체험 버튼은 실제로 저장하지 않는다는 SnackBar를 표시한다(P01). 버튼의 선택 상태나 관심 상품 목록을 유지하지 않는다.

영상은 해당 시연 흐름을 보여 주는 근거다. 모든 상태의 테스트 완료나 실제 사용자 대상 사용성 검증을 뜻하지 않는다. 후속 평가에서는 가격·치수 비교가 쉬운지, 오류 후 다음 행동을 이해하는지 확인한다.

## 5. 상태관리 포인트 (표시만 — 구현하지 않는다)

아래 표는 향후 기능의 상태관리 후보를 설명한다.
현재 검색·필터·개인화 추천·영구 저장을 구현하지 않는다.
조건 입력 UI도 이번 세 화면에 추가하지 않는다.

| 바뀌는 데이터 | 향후 변경 지점 | 보이는 곳 | 코드 주석 위치 |
|---|---|---|---|
| 공간·예산 조건 | 향후 조건 입력 | A-2·A-3 목록, C-3 추천 목록 | `a_list_screen.dart` |
| 관심 상품 여부 | B-5 버튼 | B-5 버튼, A-2·A-3 카드 | `b_detail_screen.dart` |
| 개인화 추천 결과 | 향후 조건 변경 | C-3 추천 목록 | `c_result_sheet.dart` |

```dart
// STATE: 공간·예산 조건 → A-2·A-3 상품 목록, C-3 추천 목록 (현재 미구현)
// STATE: 관심 상품 여부 → B-5 버튼, A-2·A-3 카드 (현재 저장하지 않음)
// STATE: 개인화 추천 결과 → C-3 추천 목록 (현재 고정 예시만 표시)
```

현재 허용된 화면 표시는 다음과 같이 처리한다.

- GET 로딩·오류·빈 상태: `FutureBuilder`.
- GET 재시도: `setState`로 Future 다시 요청.
- 탭 선택: `TabBar`·`TabBarView`.
- 화면 이동: push/pop과 modal.
- 관심 상품 체험: SnackBar만 표시.
- 추천 예시: 미리 작성한 상수만 표시.
