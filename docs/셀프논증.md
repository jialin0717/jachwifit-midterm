리뷰 번호는 `docs/리뷰분석.md`의 R01–R04를 사용한다. 실제 사용자 조사나 사용성 평가를 실시한 것으로 서술하지 않는다.

## 3. 쟁점별 논증

### 쟁점 1. 핵심 가치는 치수와 가격 확인에 둔다

**주장**
작은 공간에 놓을 수납 상품의 치수와 가격을 쉽게 확인하도록 돕는 것을 핵심 가치로 제안한다. 많은 상품 중 선택 부담을 줄이는 것은 보조 목표로 둔다.

**AI 반론**
IKEA에는 이미 분류와 3D 제품 확인을 긍정적으로 평가한 리뷰가 있다. 따라서 기존 앱에 기능이 없다고 주장해서는 안 된다. 자취핏에도 자동 필터링이나 실제 AI 추천 계산이 없으므로, 사용자에게 맞는 상품을 자동으로 찾아 준다고 설명할 수 없다.

**재반론·수정안**
새 기능의 유무보다 이용 상황과 정보 배치에 집중한다. 가격·치수·용도를 목록과 상세 화면에서 확인하도록 하고, 추천 모달은 고정 후보를 보여 주는 UI 시연으로 설명한다. 목표는 기존 IKEA 전체 기능의 대체가 아니라 작은 공간의 수납 상품 확인 흐름을 설계하는 것이다.

**실제 학생 응답과 결론**
학생은 두 방향 모두 가능하다며 AI에게 선택을 맡겼다. AI가 치수·가격 확인을 핵심으로 선택한 뒤 학생은 진행에 동의했다. 이 방향을 채택하되, 선택 이유의 초안은 AI가 정리한 것으로 기록한다.

**근거**
- R01: 2021-02-10, 1점. 치수·색상·종류 탐색 및 화면 배치에 관한 과거 불편 사례.
- R02: 2022-10-25, 5점. 크기·기능·형태별 분류에 관한 긍정 평가.
- R03: 2024-04-23, 5점. 제품을 살펴보며 집과의 적합성을 판단하는 경험에 관한 긍정 평가.
- P02: 실생활 판단에 필요한 가격과 치수 단위를 제시한다.
- P06: 필요한 정보를 화면에 보여 주어 기억 부담을 줄이는 방향으로 설계한다.
- P08: 이번 이용 상황과 관련된 정보를 중심으로 구성한다.

**전·후 비교**
- 전: 수납 상품 탐색과 추천 모달이 있는 프로토타입으로 소개했다.
- 후: 치수·가격 확인을 핵심 가치로 명시하고, 추천 모달의 시연 범위를 구분했다.
- 이번 변화는 기획 설명의 구체화이다. 새로운 추천 알고리즘이나 필터를 구현한 것은 아니다.

### 쟁점 2. 좁은 화면에서도 치수와 가격을 숨기지 않는다

**주장**
600dp 미만에서는 목록, 600dp 이상에서는 그리드로 표시하고, 상품명·가격·치수를 읽을 수 있도록 한다.

**AI 반론**
그리드에 많은 정보를 넣으면 카드 높이가 부족하거나 화면이 복잡해질 수 있다. 실제 실행 중에도 카드 하단의 4px 오버플로 로그가 발생했다. 따라서 넓은 화면에서 그리드를 사용한다는 사실만으로 가독성이 확보되는 것은 아니다.

**재반론·수정안**
핵심 정보인 치수와 가격을 단순히 생략하지 않고 줄바꿈과 카드 높이를 조정한다. 좁은 화면은 한 열로 보여 준다. 오버플로에 대해서는 카드 높이 계산의 여유 공간을 늘리는 수정안을 제시했다. 다만 이 조정만으로 모든 창 크기와 글자 크기에서 문제가 해결되었다고 단정하지 않는다.

**결론과 학생 판단**
핵심 정보를 생략하지 않는 방향을 채택한다. 학생은 상품명·가격·치수를 전체 표시하고, 필요하면 카드가 조금 높아지는 방안에 동의했다. 이 동의는 2026-10-25 대화에서 확인했다. 목록·그리드 전환 구조를 유지했다. 이후 화면·영상, 599·600·1024 너비의 위젯 테스트와 새 clone의 좁은 화면 확인을 근거로 현재 확인 범위를 기록한다.

**근거**
- R01: 모바일 화면 배치와 상품 탐색에 관한 역사적 불편 사례.
- P06: 비교할 치수·가격을 화면에서 확인할 수 있게 한다.
- P08: 핵심 정보의 우선순위와 여백을 조정한다.
- 실행 증거: 오버플로 로그 캡처와 이후 넓은 화면·좁은 화면 캡처.

**전·후 비교**
- 전: 2026-10-25 실행 과정에서 4px 오버플로 로그가 확인되었다.
- 후: 카드 높이 계산에 16의 여유를 더한 수정과 이후 넓은 화면·좁은 화면의 상품 표시를 확인했다. 2026-10-26 원본과 별도 clone에서 위젯 테스트 7개 및 직접 Dart 분석이 통과했고, 학생은 clone의 좁은 화면도 정상이라고 보고했다.
- 테스트 너비 외 모든 창 크기·글자 크기와 터미널 로그 전체를 검증한 결과는 아니다.
- 공개 기록에는 과거 기획 기준점 `v1-plan`이 없다. 이 레이아웃 변경을 별도 과거 커밋의 전·후 diff로 입증하지 않는다.

### 쟁점 3. 조회 실패 안내와 재시도 버튼을 화면에 유지한다

**주장**
상품 목록 조회가 실패하면 실패 상태와 다시 시도 버튼을 화면에 표시한다.

**AI 반론**
재시도 버튼이 있어도 서버가 꺼져 있으면 사용자가 반복해서 눌러도 해결되지 않는다. 개발용 서버 주소만으로 원인을 설명하면 일반 사용자는 다음 행동을 이해하기 어려울 수 있다.

**재반론·수정안**
현재 수업용 시연에서는 로컬 mock 서버 연결 상태를 확인해야 한다. 실패 화면을 유지하여 빈 목록이나 로딩 상태와 구분하고, 서버가 복구된 뒤 사용자가 다시 조회할 수 있게 한다. 일반 사용자용으로 발전시킬 때에는 서버 주소보다 연결 확인 등 이해하기 쉬운 안내를 우선하는 방안을 검토한다.

**결론과 학생 판단**
오류 안내와 재시도 버튼을 화면에 유지한다. 학생은 잠깐 나타났다가 사라지는 안내보다, 오류와 재시도 수단을 계속 보여 주는 방향에 동의했다. 이 동의는 2026-10-25 대화에서 확인했다. 일반 사용자용 안내 문구 개선은 후속 검토 사항이며, 이미 구현한 것으로 기록하지 않는다.

**근거**
- R04: 2022-11-04, 2점. 결제 결과 안내 부족에 관한 과거 사례.
- 이 리뷰는 상품 목록 조회 실패를 직접 설명한 것이 아니다. 결과와 상태를 명확하게 알려야 한다는 설계 시사점으로 참고했다.
- P01: 로딩·오류·빈 상태를 구분한다.
- P09: 오류를 알리고 다시 시도할 수 있는 수단을 제공한다.
- 실행 증거: 기존 오류 화면과 복구 화면, `docs/영상/p09.mov`의 오류 안내 → 서버 재시작 → 다시 시도 → 목록 복구. 서버 중지 조작 자체는 이 영상에 나오지 않는다. 새 clone에서도 오류 화면을 확인했으며, 학생이 서버 재시작 뒤 새로고침 없이 다시 시도를 눌러 목록 복구에 성공했다고 보고했다.

**전·후 비교**
- 실패 상태: mock 서버가 중지된 상황에서 오류 안내가 표시되었다.
- 복구 상태: 서버 재시작 뒤 상품 목록이 다시 표시되었다.
- 이것은 실패·복구 상태의 비교이며, 코드 수정 전·후 비교는 아니다.
- 과거에 SnackBar만 사용했다가 오류 화면으로 바꿨다는 이력은 확인되지 않았으므로 기록하지 않는다.
